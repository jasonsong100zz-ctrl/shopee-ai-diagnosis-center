# Chrome 登录态优先运行

## 目标

固定链接竞品采集优先在用户已经登录的 Google Chrome 配置中运行。这样 Shopee 页面使用用户现有的登录状态和正常浏览器环境，减少重新登录和触发流量验证的概率。

## 选择规则

当用户提到“谷歌浏览器”“已登录 Chrome”“缓存账号”或要求复用现有登录态时：

1. 选择 Chrome 控制能力或当前 Chrome 扩展，不选择内置浏览器。
2. 优先检查 FM 竞品监控扩展是否已经在 Chrome 的扩展列表中启用。
3. 已安装时，直接打开或切换到 Shopee 商品页，从 FM 扩展弹窗启动任务。
4. 未安装时，使用 Skill 内的 `scripts/install-chrome-extension.ps1` 准备扩展并打开 `chrome://extensions`，完成一次“加载已解压的扩展程序”。
5. 只有确认扩展在 Chrome 中可见并启用后，才报告“安装完成”或开始依赖扩展的采集。

## 为什么不能静默安装

Chrome 不允许普通网页或 Skill 在用户不知情的情况下把未签名的本地扩展静默安装到现有浏览器。安装脚本只能完成以下准备工作：

- 复制 bundled extension 到稳定的用户目录；
- 打开 `chrome://extensions`；
- 输出需要选择的扩展目录。

“开发者模式”和“加载已解压的扩展程序”仍需用户可见确认，或由用户明确授权的 Chrome UI 自动化完成。不要伪造安装成功状态，也不要修改 Chrome 的密码、Cookie 或配置数据库。

## 登录态边界

- FM 扩展运行在当前 Chrome 配置中，Shopee 登录状态由 Chrome 自己维护。
- Skill、脚本和扩展不得读取、导出、复制或保存 Chrome 密码、Cookie、Local Storage 或会话数据库。
- 不要为了获得登录态而启动新的临时 Chrome 配置，除非用户明确要求并愿意重新登录。
- 不要关闭用户正在使用的 Chrome 来替换启动参数；如需 CDP，必须使用用户明确启动并授权的 Chrome 调试会话。

## 采集流程

1. 确认 Chrome 中已登录目标 Shopee 市场。
2. 确认 `FM 竞品监控` 扩展已启用。
3. 在扩展中粘贴 Google Sheet 或 CSV 清单，默认选择离线 CSV。
4. 点击“开始监控”，让扩展在当前 Chrome 中逐条打开商品链接。
5. 遇到登录、CAPTCHA、滑块或流量验证时，扩展暂停；由用户在当前可见页面人工处理，再点击“验证后继续”。
6. 状态显示“监控完成”后点击“下载本次结果 CSV”，并通过 `chrome://downloads` 确认文件。

## 不同执行方式的取舍

| 方式 | 是否复用现有 Chrome 登录态 | 默认建议 | 说明 |
| --- | --- | --- | --- |
| 当前 Chrome + FM 扩展 | 是 | 首选 | 人工启动、页面可见、遇验证可暂停 |
| 已授权 Chrome CDP | 取决于连接的 Chrome 配置 | 仅在用户明确配置后使用 | 不能把独立临时配置误称为用户缓存登录 |
| 内置浏览器 | 通常不是用户 Chrome 登录态 | 不用于本流程 | 容易重新触发登录或流量验证 |
| Headless Chromium | 否 | 禁止作为默认 | 更容易被平台识别，不能处理人工验证 |
